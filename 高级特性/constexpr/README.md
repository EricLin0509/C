# constexpr

`constexpr` (constant expression) 是 C23 引入的新特性，是在C语言真正意义上的常量表达式

可以用来定义常量表达式。常量表达式是指在编译期间可以计算出结果的表达式

## 示例

假设我们用宏定义一个表达式

```c
#define SUM 100 + 200
```

如果我们单独使用 `SUM`，不会发生什么

```c
int a = SUM;
```

### 神奇的BUG

如果现在用想在这个表达式的基础上乘以一个常量，会发生什么

```c
int b = SUM * 2;
printf("SUM * 2 = %d\n", b);
```

此时的输出

```
SUM * 2 = 500
```

这是一个很奇怪的结果，因为我们期望 `SUM * 2` 等于 `600`，而不是 `500`

这是因为 `SUM` 是一个宏定义，它只是单纯地做文字替换，而不是在编译时计算出结果

文字替换后的表达式是这样的

```c
int b = 100 + 200 * 2;
```

C23之前的做法是在宏定义中添加括号

```c
#define SUM (100 + 200)
```

但如果这个表达式复杂时，就会导致括号嵌套地狱

### constexpr

但是如果我们把宏定义改为 `constexpr`，就可以正常算出结果

```c
constexpr int sum = 100 + 200;
int b = sum * 2;
printf("sum * 2 = %d\n", b);
```

相比宏定义，`constexpr` 有类型，可以避免一些隐患

这是因为宏定义是在预处理时期完成的，而 `constexpr` 保证该变量的值是编译期常量，可以在需要常量表达式的上下文中使用 (如数组大小、case 标签、位域宽度等)

## 与 `const` 的区别

`const` 表示"只读"，即程序运行期间不能修改，但它的值**不一定**在编译期就能确定

`constexpr` 表示"编译期常量"，它的值**必须**在编译期就能计算出来

### 核心区别：能否用于常量表达式语境

```c
constexpr int size = 10;
int arr[size];          // 合法：size 是常量表达式

const int n = 10;
int arr2[n];            // C23 之前：VLA（变长数组），不是常量表达式
```

C 语言中，数组大小、`case` 标签、位域宽度、枚举值等位置**必须**使用常量表达式，`const` 变量不满足要求，而 `constexpr` 变量可以

### `const` 的值可以不在编译期确定

```c
int get_value(void);

const int x = get_value();     // 合法：const 只要求只读，值可以运行时确定
constexpr int y = get_value(); // 错误：constexpr 要求值必须在编译期可计算
```

### 总结

| 特性 | `const` | `constexpr` |
|------|---------|-------------|
| 语义 | 只读 | 编译期常量 |
| 值的确定时机 | 可以在运行时 | 必须在编译期 |
| 可用于常量表达式语境 | 否 | 是 |
| 可用运行时值初始化 | 是 | 否 |
